01Pengenalan Go, Fiber & Konsep "Laravel Style"

Tujuan bab
  • Memahami apa itu Go dan Fiber.
  • Memahami maksud "Laravel style" di modul ini.
  • Mengenal padanan fitur Laravel di dunia Go.

Apa itu Go?

Go (atau Golang) adalah bahasa pemrograman buatan Google. Go terkenal karena:

  • Cepat — kode Go di-compile menjadi satu file program (binary). Tidak perlu interpreter seperti PHP.
  • Sederhana — aturan bahasanya sedikit, mudah dipelajari.
  • Mudah di-deploy — cukup upload satu file binary ke server, lalu jalankan.

Apa itu Fiber?

Fiber adalah web framework untuk Go. Fiber mengurus hal-hal seperti routing, request, response, middleware, dan view. Fiber terinspirasi dari Express.js (Node.js), jadi cara menulisnya ringkas.

Bedanya dengan Laravel: Laravel itu framework "lengkap" (ORM, auth, queue, dll sudah ada). Fiber itu framework "ringan" — hanya inti web-nya saja. Fitur lain kita tambahkan sendiri dengan library pilihan.

Apa maksud "Laravel style"?

Go tidak memaksa struktur folder tertentu. Akibatnya, banyak project Go berantakan. Di modul ini, kita meniru struktur dan pola Laravel: ada folder app/http/controllers, app/models, routes, resources/views, database, dan file .env. Hasilnya, developer Laravel langsung merasa "di rumah".

go run vs go build

Ada dua cara menjalankan program Go:

  • go run . — compile lalu langsung jalankan. File hasil compile dibuang. Cocok saat belajar dan development.
  • go build — compile menjadi satu file program (binary) yang bisa dijalankan kapan saja, bahkan di komputer yang tidak punya Go.

Di Windows, file hasilnya bernama hello.exe dan dijalankan dengan .\hello.exe. Kita akan memakai go build lagi di bab deploy, karena aplikasi web Go cukup di-upload sebagai satu file ini ke server.

ℹ️ Apa itu compile?Komputer tidak mengerti kode Go secara langsung. Compile artinya menerjemahkan kode Go menjadi bahasa mesin. Ibarat menerjemahkan buku sekali saja, lalu hasilnya bisa dibaca berkali-kali dengan cepat. PHP tidak begitu: PHP dibaca ulang oleh interpreter setiap kali dijalankan.

Membaca pesan error

Error itu teman, bukan musuh. Go sangat ketat: banyak kesalahan langsung ditolak sebelum program berjalan. Ini bagus, karena bug ketahuan lebih awal. Pesan error Go selalu punya pola yang sama:

Jadi, lihat nomor barisnya, buka baris itu, lalu baca penjelasannya. Berikut tiga error yang paling sering dialami pemula.

1. Variabel dibuat tapi tidak dipakai

Artinya: di baris 7 kolom 2, variabel umur dibuat (declared) tapi tidak pernah dipakai (not used). Go menganggap ini sampah, jadi programnya ditolak. Solusinya: pakai variabel itu, atau hapus.

2. Import tapi tidak dipakai

Sama seperti variabel, package yang di-import juga wajib dipakai. Hapus "os" dari daftar import. Kabar baiknya, extension Go di VS Code biasanya menambah dan menghapus import secara otomatis.

3. Kurung kurawal di baris baru

Di Go, kurung kurawal pembuka { wajib berada di baris yang sama dengan func, if, for, dan sebagainya. Tulis func main() {, bukan dipisah ke baris berikutnya.

04Variabel, Konstanta & Tipe Data

Tujuan bab
  • Membuat variabel dengan var dan :=.
  • Mengenal tipe data dasar: int, float64, string, bool.
  • Memahami zero value dan konstanta.
  • Mengubah tipe data dan mencetak teks rapi dengan fmt.Printf.

Variabel itu seperti kotak berlabel

Bayangkan kamu pindahan rumah. Barang dimasukkan ke kardus, lalu kardusnya diberi label: "Buku", "Piring". Variabel itu kardusnya. Label adalah nama variabel, isinya adalah nilai.

Di Go, setiap kardus juga punya jenis yang tetap, disebut tipe data. Kardus khusus angka tidak bisa diisi teks. Inilah bedanya dengan PHP, yang membolehkan isi variabel berganti jenis kapan saja.

Tiga cara membuat variabel

  • var nama string = "Budi" — cara lengkap: kata var, nama, tipe, lalu nilai.
  • var kota = "Jakarta" — tipe boleh tidak ditulis. Go melihat nilainya (teks), jadi tipenya pasti string.
  • umur := 25 — cara singkat, paling sering dipakai. Tanda := artinya "buat variabel baru dan isi". Hanya boleh dipakai di dalam function.
  • umur = 26 — tanda = (tanpa titik dua) artinya "ganti isi variabel yang sudah ada".
⚠️ := vs =:= untuk membuat variabel baru. = untuk mengubah variabel yang sudah ada. Menulis umur := 30 dua kali di tempat yang sama akan error no new variables on left side of :=.
🟥 Kalau di PHP/Laravel...PHP: $umur = 25; $umur = "dua lima"; boleh. Go: umur := 25 lalu umur = "dua lima" ditolak, karena umur sudah bertipe int.

Mengubah tipe data (konversi)

Karena tipe di Go ketat, kadang kita perlu mengubah tipe secara manual:

  • a / b dengan dua int menghasilkan int (3), sisa pembagian dibuang.
  • float64(a) mengubah int menjadi float64. Formatnya: TipeTujuan(nilai).
  • int(nilai) mengubah desimal menjadi bulat dengan membuang angka di belakang koma (bukan membulatkan).
  • strconv.Itoa (integer to ASCII) mengubah angka menjadi teks.
  • strconv.Atoi (ASCII to integer) mengubah teks menjadi angka. Karena teksnya bisa saja bukan angka (misal "abc"), function ini mengembalikan dua nilai: hasilnya dan err. Kalau berhasil, err bernilai <nil> (artinya "tidak ada error").
⚠️ Jangan pakai string(25)Untuk mengubah angka menjadi teks, pakai strconv.Itoa(25). string(25) bukan menghasilkan "25", melainkan karakter dengan kode 25 (karakter aneh yang tidak terlihat).
💡 Kaitannya dengan FiberSemua data dari URL dan form datang sebagai teks. Misalnya /posts/5: angka 5 di sana masih berupa string. Itu sebabnya nanti ada c.ParamsInt("id") yang mengubahnya menjadi angka dan bisa mengembalikan error.

Sedikit tentang string

String digabung dengan +. len() menghitung jumlah byte, bukan jumlah huruf. Untuk huruf biasa (A–Z), 1 huruf = 1 byte. Tapi huruf seperti é atau emoji memakai lebih dari 1 byte. Untuk menghitung jumlah huruf sebenarnya, ubah dulu menjadi []rune. Rune adalah sebutan Go untuk satu karakter.

🟥 Kalau di PHP/Laravel...PHP menggabung string dengan titik (.), Go dengan plus (+). len() di Go mirip strlen(), sedangkan len([]rune(s)) mirip mb_strlen().

05Operator & Percabangan

Tujuan bab
  • Memakai operator aritmatika, perbandingan, dan logika.
  • Membuat keputusan dengan if, else if, else.
  • Memahami pola if err := ...; err != nil yang akan sering muncul.
  • Memakai switch sebagai pengganti if yang panjang.

Operator aritmatika

Operator adalah simbol untuk menghitung atau membandingkan. Yang dasar sama seperti pelajaran matematika di sekolah:

  • 17 / 5 menghasilkan 3, karena dua-duanya int. Bagian desimal dibuang.
  • 17 % 5 (dibaca "modulo") menghasilkan sisa bagi, yaitu 2. Berguna untuk mengecek ganjil/genap.
  • skor += 5 adalah singkatan skor = skor + 5. Ada juga -=, *=, /=.
  • skor++ menambah 1. skor-- mengurangi 1.
ℹ️ ++ di GoDi Go, skor++ adalah perintah tersendiri, bukan nilai. Jadi x := skor++ tidak boleh. Ini sengaja dibuat supaya kode lebih mudah dibaca.

Percabangan dengan if

Percabangan itu seperti persimpangan jalan: "Jika hujan, bawa payung. Jika tidak, pakai topi." Program memilih jalur berdasarkan kondisi.

Go memeriksa kondisi dari atas ke bawah. Begitu ada yang true, blok itu dijalankan dan sisanya dilewati. Nilai 78 tidak memenuhi >= 85, tapi memenuhi >= 70, jadi yang tercetak "Grade B".

if dengan statement awal

Ini pola yang sangat sering muncul di Go, termasuk di semua controller Fiber nanti:

Baca if n, err := strconv.Atoi("42"); err != nil { dalam dua bagian, dipisah titik koma:

  1. Sebelum titik koma: jalankan strconv.Atoi, simpan hasilnya di n dan err.
  2. Sesudah titik koma: kondisinya. Jika err tidak sama dengan nil (artinya ada error), jalankan blok pertama.

Kalau pilihannya banyak, switch lebih enak dibaca daripada deretan else if:

  • case "sabtu", "minggu": — satu case boleh berisi beberapa nilai, dipisah koma.
  • default: — dijalankan jika tidak ada case yang cocok, seperti else.
  • Tidak perlu break. Go otomatis berhenti setelah satu case cocok.
  • switch { tanpa variabel — setiap case berisi kondisi sendiri. Ini pengganti if-else if yang panjang.

06Perulangan

Tujuan bab
  • Memahami bahwa Go hanya punya satu kata kunci perulangan: for.
  • Memakai for dalam bentuk klasik, bentuk "while", dan bentuk tak terbatas.
  • Menghentikan dan melewati putaran dengan break dan continue.
  • Menelusuri data dengan range.

Perulangan dipakai untuk mengerjakan hal yang sama berkali-kali. Contohnya menampilkan semua post di halaman blog: kodenya ditulis sekali, lalu diulang untuk setiap post.

Kabar baik: Go hanya punya satu kata kunci perulangan, yaitu for. Tidak ada while, do-while, atau foreach. Semua bentuk itu ditulis dengan for.

Bentuk 1: for klasik

Ada tiga bagian, dipisah titik koma:

  1. i := 1 — awal: dijalankan sekali sebelum perulangan dimulai.
  2. i <= 5 — kondisi: dicek sebelum setiap putaran. Jika false, perulangan berhenti.
  3. i++ — langkah: dijalankan di akhir setiap putaran.

Bentuk 2: for dengan kondisi saja (pengganti while)

Dipakai ketika kita tidak tahu berapa kali harus mengulang. Kita hanya tahu kapan harus berhenti.

Selama saldo masih di bawah 150.000, tambahkan 20.000. Setelah 3 kali, saldo menjadi 160.000 dan kondisinya false, jadi perulangan berhenti.

🟥 Kalau di PHP/Laravel...while ($saldo < 150000) { ... } di PHP sama dengan for saldo < 150000 { ... } di Go.

Bentuk 3: for tak terbatas, break, dan continue

  • for { tanpa kondisi akan berputar terus. Harus ada break supaya bisa berhenti.
  • break — keluar dari perulangan sekarang juga.
  • continue — lewati sisa kode di putaran ini, langsung lanjut ke putaran berikutnya. Di contoh ini, angka genap dilewati sehingga hanya angka ganjil yang tercetak.
⚠️ Perulangan tanpa akhirJika kamu lupa break atau kondisinya tidak pernah false, program berputar selamanya. Tekan Ctrl + C di terminal untuk menghentikannya.
ℹ️ Fakta menarikServer web adalah contoh perulangan tak terbatas. app.Listen(":3000") di Fiber terus menunggu dan melayani request selamanya, sampai kamu menekan Ctrl + C.

Bentuk 4: for ... range

range dipakai untuk menelusuri isi kumpulan data satu per satu. Slice (daftar) akan dibahas detail di bab berikutnya. Untuk sekarang, anggap []string{...} adalah daftar teks.

  • Pada slice, range memberikan index (nomor urut mulai dari 0) dan nilai.
  • Jika index tidak dibutuhkan, ganti dengan _ (garis bawah). Ingat, variabel yang tidak dipakai akan error. _ artinya "buang saja".
  • Pada string, range memberikan posisi dan karakter (rune). string(huruf) mengubah rune kembali menjadi teks.
  • for i := range 3 (Go 1.22 ke atas) mengulang 3 kali dengan i = 0, 1, 2.
🟥 Kalau di PHP/Laravel...foreach ($buah as $i => $b) di PHP sama dengan for i, b := range buah di Go. Di Blade kamu menulis @foreach, di view Go nanti {{range .posts}}.

07Array, Slice & Map

Tujuan bab
  • Membedakan array dan slice.
  • Menambah, mengambil sebagian, dan membuat slice.
  • Menyimpan pasangan kunci-nilai dengan map.
  • Memahami bahwa fiber.Map hanyalah sebuah map.

Sejauh ini satu variabel hanya menyimpan satu nilai. Padahal aplikasi sering butuh menyimpan banyak nilai sekaligus: daftar post, daftar user, data form. Go punya tiga wadah untuk ini.

WadahAnalogiContoh pemakaian
ArrayRak telur: jumlah lubangnya tetapJarang dipakai langsung
SliceDaftar belanja: bisa ditambah terusDaftar post dari database
MapBuku telepon: cari nomor lewat namaData yang dikirim ke view, pesan error validasi

Array: ukurannya tetap

  • [3]int artinya array berisi tepat 3 int. Ukuran ini tidak bisa berubah.
  • Index dimulai dari 0. Jadi isi pertama adalah nilai[0], isi terakhir nilai[2].
  • len(nilai) memberikan jumlah isinya.
  • Mengakses index di luar batas (misal nilai[3]) menyebabkan error.

Slice: daftar yang bisa bertambah

Dalam praktik, kamu hampir selalu memakai slice. Cara menulisnya mirip array, tapi tanpa angka di dalam [].

  • []string{"apel", "jeruk"} — slice berisi string. Tanpa angka di dalam [].
  • append(buah, "mangga", "pisang") — menambah isi di akhir. Wajib disimpan lagi ke variabel: buah = append(buah, ...).
  • buah[1:3] — ambil dari index 1 sampai sebelum index 3. Hasilnya index 1 dan 2.
  • buah[:2] artinya dari awal sampai sebelum 2. buah[2:] artinya dari 2 sampai akhir.
  • make([]int, 3) — membuat slice berisi 3 angka bernilai zero value (0).
  • var kuadrat []int — slice kosong, siap diisi lewat append.
  • cap() (kapasitas) adalah jumlah tempat yang sudah disiapkan Go di belakang layar. Go menambah kapasitas secara otomatis, jadi kamu jarang perlu memikirkannya.
🟥 Kalau di PHP/Laravel...Slice mirip array biasa di PHP: $buah[] = "mangga"; sama dengan buah = append(buah, "mangga"). buah[1:3] mirip array_slice($buah, 1, 2).
💡 Kaitannya dengan FiberDi controller nanti kita menulis var posts []models.Post, lalu database mengisi slice ini dengan semua post. Setelah itu slice dikirim ke view dan ditampilkan dengan {{range .posts}}.

Map: pasangan kunci dan nilai

Map menyimpan data dalam bentuk kunci → nilai. Seperti daftar menu di warung: nama menu (kunci) → harga (nilai).

  • map[string]int artinya kuncinya string, nilainya int.
  • harga["roti"] = 12000 — menambah data baru, atau mengganti jika kuncinya sudah ada.
  • Membaca kunci yang tidak ada tidak membuat error. Hasilnya zero value (0 untuk int).
  • h, ok := harga["susu"] — pola "comma ok". ok bernilai true jika kuncinya ada. Ini cara yang benar untuk mengecek keberadaan kunci.
  • delete(harga, "roti") menghapus satu kunci. len(harga) menghitung jumlah kunci.
  • fmt.Println mencetak map dengan kunci yang sudah diurutkan, supaya mudah dibaca. Tapi ingat, range pada map tetap acak.
🟥 Kalau di PHP/Laravel...Map adalah "array asosiatif" di PHP: $harga = ['kopi' => 15000];. isset($harga['susu']) setara dengan _, ok := harga["susu"].
💡 Kaitannya dengan FiberFungsi validasi di modul ini mengembalikan map[string]string, misalnya {"email": "Kolom email wajib diisi."}. Kuncinya nama field, nilainya pesan error. Kalau map-nya kosong (len(errs) == 0), berarti data valid.

Menggabungkan slice dan map

  • []map[string]string — slice yang setiap isinya map. Bentuknya mirip hasil query database: banyak baris, setiap baris punya kolom.
  • map[string][]string — map yang setiap nilainya slice. Satu kunci bisa punya banyak nilai.

fiber.Map itu hanya sebuah map

Di bab Fiber nanti, kamu akan sering melihat fiber.Map{"title": "Beranda"}. Jangan bingung. Ini bukan hal baru:

  • type Map map[string]any membuat nama baru (Map) untuk tipe map[string]any. Fiber melakukan hal yang persis sama.
  • any artinya "boleh tipe apa saja". Jadi satu map bisa berisi string, angka, bool, bahkan slice.
🟥 Kalau di PHP/Laravel...c.Render("home", fiber.Map{"title": "Beranda"}) di Fiber sama dengan return view('home', ['title' => 'Beranda']); di Laravel.

08Function

Tujuan bab
  • Membuat function dengan parameter dan nilai kembali.
  • Memakai function yang mengembalikan lebih dari satu nilai.
  • Mengenal variadic, function sebagai nilai, anonymous function, dan closure.
  • Memahami bentuk handler dan middleware Fiber sebelum memakainya.

Function adalah kumpulan kode yang diberi nama, supaya bisa dipakai berulang-ulang. Bayangkan resep masakan: ditulis sekali, lalu bisa dimasak kapan saja. Bahan-bahannya disebut parameter, masakan jadinya disebut nilai kembali (return value).

Function dasar

Baca func tambah(a int, b int) int seperti ini: "function bernama tambah, menerima a dan b bertipe int, lalu mengembalikan sebuah int".

  • Tipe ditulis setelah nama parameter: a int, bukan int a.
  • Jika beberapa parameter bertipe sama, cukup tulis tipenya sekali: (a, b int).
  • return mengirim hasil kembali ke pemanggil.
  • Function tanpa tipe kembali (seperti sapa) hanya melakukan sesuatu, tanpa mengembalikan nilai.
🟥 Kalau di PHP/Laravel...PHP: function tambah(int $a, int $b): int. Go: func tambah(a, b int) int. Idenya sama, urutannya terbalik.

Mengembalikan lebih dari satu nilai

Ini salah satu ciri khas Go. Function boleh mengembalikan dua nilai atau lebih. Paling sering: hasil dan error.

  • (int, error) — function ini mengembalikan dua nilai: sebuah int dan sebuah error.
  • errors.New("...") membuat error baru berisi pesan.
  • nil artinya "kosong / tidak ada". Mengembalikan nil sebagai error berarti "semuanya lancar".
  • Pemanggil menerima keduanya: hasil, err := bagi(10, 2), lalu memeriksa if err != nil.
  • _, terbesar := minMax(...) — garis bawah _ (blank identifier) membuang nilai yang tidak dibutuhkan.
ℹ️ Kenapa Go tidak pakai try/catch?Di Go, error adalah nilai biasa yang dikembalikan function. Kamu dipaksa melihat dan menangani error tepat di tempat terjadinya. Kodenya jadi sedikit lebih panjang, tapi alurnya sangat jelas. Bab berikutnya membahas error secara lengkap.

Variadic: jumlah argumen bebas

angka ...int artinya function ini menerima berapa pun int, bahkan nol. Di dalam function, angka berupa slice []int. Untuk mengirim isi slice yang sudah ada, tambahkan ... di belakangnya: jumlahkan(nilai...).

ℹ️ Sudah sering kamu pakaifmt.Println adalah function variadic. Itulah sebabnya ia bisa menerima berapa pun nilai.

Function adalah nilai

Di Go, function bisa diperlakukan seperti data biasa: disimpan di variabel, atau dikirim ke function lain sebagai argumen.

  • f := teriak — tanpa tanda kurung. Kita menyimpan function-nya, bukan memanggilnya.
  • ubah func(string) string — parameter bertipe function: "function yang menerima string dan mengembalikan string".
  • Fungsi terapkan tidak peduli function mana yang dikirim, asalkan bentuknya cocok. Jadi kita bisa mengirim teriak atau sapa.

Anonymous function: function tanpa nama

Function tanpa nama ditulis langsung di tempat dibutuhkan. Bisa disimpan di variabel, langsung dipanggil dengan () di belakangnya, atau dikirim sebagai argumen.

💡 Kaitannya dengan FiberIngat kode Hello World Fiber yang akan kamu tulis nanti:
app.Get("/", func(c *fiber.Ctx) error { return c.SendString("Halo") })
Bagian func(c *fiber.Ctx) error { ... } adalah anonymous function yang dikirim ke app.Get. Fiber menyimpannya, lalu memanggilnya setiap kali ada request ke /. Persis seperti jalankan(func(...) {...}) di atas.
🟥 Kalau di PHP/Laravel...Sama seperti closure di route Laravel: Route::get('/', function () { return 'Halo'; });

Closure: function yang "mengingat"

buatPenghitung mengembalikan sebuah function. Function itu terus "mengingat" variabel jumlah milik pembuatnya, walaupun buatPenghitung sudah selesai berjalan. Setiap panggilan buatPenghitung() membuat jumlah baru, jadi hitungA dan hitungB tidak saling mengganggu.

Function yang membawa "ingatan" seperti ini disebut closure. Ibarat celengan: setiap celengan menyimpan uangnya sendiri.

Mengintip cara kerja handler & middleware Fiber

Sekarang kita gabungkan semuanya. Program berikut adalah tiruan kecil cara kerja Fiber. Tidak memakai Fiber sungguhan, tapi idenya sama.

  • type Handler func(path string) string memberi nama untuk sebuah bentuk function. Di Fiber, bentuknya func(c *fiber.Ctx) error dan namanya fiber.Handler.
  • home adalah "controller": anonymous function yang membalas request.
  • Logger dan Auth adalah middleware: function yang menerima handler berikutnya (next), lalu mengembalikan handler baru (closure) yang membungkusnya.
  • Logger(Auth(home)) menyusun lapisan seperti bawang: request melewati Logger, lalu Auth, baru sampai ke home.
  • Auth bisa memotong perjalanan dengan tidak memanggil next. Itu yang terjadi untuk path /admin.
🟥 Kalau di PHP/Laravel...Memanggil next(path) di sini sama dengan return $next($request); di middleware Laravel. Di Fiber nanti bentuknya return c.Next(). Middleware Auth() di modul ini juga berupa function yang mengembalikan fiber.Handler, persis seperti contoh di atas.

09Error Handling & defer

Tujuan bab
  • Memahami bahwa error di Go adalah nilai biasa, bukan exception.
  • Membuat error dengan errors.New dan fmt.Errorf, lalu memeriksanya dengan errors.Is dan errors.As.
  • Memakai defer untuk "beres-beres" otomatis.
  • Mengenal panic dan recover, serta kaitannya dengan Fiber.

Program yang baik bukan program yang tidak pernah gagal. Program yang baik adalah program yang tahu saat ia gagal, lalu bereaksi dengan benar. File tidak ada, database mati, user mengisi huruf di kolom angka — semua ini pasti terjadi. Bab ini mengajarkan cara Go menangani kegagalan.

Error adalah nilai biasa

Di PHP atau JavaScript, kegagalan biasanya "dilempar" (throw) lalu "ditangkap" (try/catch). Go memilih cara yang lebih sederhana: function yang bisa gagal mengembalikan error sebagai nilai terakhir. Pemanggil wajib memeriksanya sendiri.

Analogi: kamu menitip beli kopi ke teman. Teman pulang membawa dua hal: kopinya dan catatan. Kalau catatannya kosong, berarti semua lancar. Kalau catatannya berisi "warung tutup", kamu tahu ada masalah dan kopinya tidak bisa dipakai.

Baris-baris penting:

  • (int, error) — function mengembalikan dua nilai. Nilai error selalu diletakkan paling akhir. Ini kesepakatan semua programmer Go.
  • errors.New("...") — membuat error baru berisi pesan.
  • return a / b, nil — nil artinya "tidak ada error". Jadi pemanggil tahu hasilnya aman dipakai.
  • if err != nil { ... return } — "jika ada error, tangani lalu berhenti". Pola ini akan kamu tulis ratusan kali. Itu normal di Go.
🟥 Kalau di PHP/Laravel...

PHP: try { $hasil = bagi(10, 0); } catch (Exception $e) { echo $e->getMessage(); }

Go: hasil, err := bagi(10, 0); if err != nil { fmt.Println(err) }

Bedanya, di Go kamu langsung melihat bahwa sebuah function bisa gagal dari tanda tangannya (error di nilai kembalian). Tidak ada error yang "melompat" diam-diam.

⚠️ Jangan buang errorKamu bisa menulis hasil, _ := bagi(10, 0) untuk mengabaikan error. Ini boleh, tapi berbahaya: kalau gagal, hasil berisi 0 dan program jalan terus seolah tidak ada apa-apa. Abaikan error hanya kalau kamu yakin betul.

Pola "kembalikan error ke atas"

Di dalam aplikasi, error biasanya tidak dicetak di tempat ia terjadi. Error diteruskan ke pemanggil, sampai tiba di tempat yang tahu harus berbuat apa. Lihat potongan dari auth_controller.go di aplikasi kita nanti:

Perhatikan bentuk kedua: if err := ...; err != nil. Ini cara singkat. Variabel err dibuat dan dicek dalam satu baris, dan hanya berlaku di dalam blok if itu.

Membungkus error: fmt.Errorf dan %w

Pesan seperti "data tidak ditemukan" kurang jelas. Data apa? Dengan fmt.Errorf kita bisa menambah keterangan. Kode %w (w = wrap) "membungkus" error asli, seperti memasukkan surat ke amplop yang diberi label. Isinya tetap bisa diperiksa.

Selain itu, kita juga bisa membuat tipe error sendiri yang membawa data tambahan. Syaratnya cuma satu: punya method Error() string. (Kenapa cukup begitu? Jawabannya ada di Bab 11 tentang interface.)

ℹ️ Ketemu lagi di aplikasi kitaDi bootstrap/app.go nanti ada kode ini: Artinya: "kalau error ini bertipe *fiber.Error, ambil kode status HTTP-nya". Saat controller menulis return fiber.ErrNotFound, error handler inilah yang mengubahnya menjadi halaman 404. Sekarang kamu tahu cara kerjanya.

defer: "kerjakan ini nanti, saat function selesai"

defer menunda sebuah perintah sampai function yang sedang berjalan selesai — entah selesai normal, lewat return di tengah, atau karena error.

Analogi: begitu masuk kamar mandi, kamu menempel catatan di pintu: "matikan lampu saat keluar". Mau keluar cepat atau lama, catatan itu pasti dijalankan. Kalau ada beberapa catatan, yang terakhir ditempel dijalankan pertama (seperti tumpukan piring: Last In, First Out).

  • defer file.Close() ditulis tepat setelah file berhasil dibuka. Jadi kita tidak mungkin lupa menutupnya, walau nanti ada return di tengah.
  • "defer 1, 2, 3" baru muncul setelah "Selesai", dengan urutan terbalik: 3, 2, 1.
  • Di dalam tulisCatatan, "(file ditutup)" tercetak saat function itu selesai, bukan saat main selesai.
💡 Di aplikasi kitaMiddleware StartSession memakai ide yang mirip: kerjakan c.Next() dulu, baru setelahnya simpan session. Pola "siapkan → kerjakan → beres-beres" sangat umum di Go.

panic dan recover

panic adalah kegagalan fatal yang langsung menghentikan program. Contohnya mengambil elemen ke-5 dari slice yang isinya cuma 2. Kamu jarang perlu memanggil panic sendiri. Untuk kegagalan biasa, selalu pakai error.

recover adalah "jaring pengaman" yang menangkap panic. recover hanya bekerja di dalam function yang di-defer.

ℹ️ Ini yang dilakukan recover.New()Di bootstrap/app.go kita memasang app.Use(recover.New()). Middleware itu memakai trik defer + recover seperti di atas untuk setiap request. Kalau satu controller panic, hanya request itu yang gagal (dapat error 500). Server tetap hidup untuk user lain.

10Struct, Method & Pointer

Tujuan bab
  • Membuat tipe data sendiri dengan struct.
  • Menempelkan function ke struct (method), dan memahami beda value receiver dan pointer receiver.
  • Memahami pointer (& dan *) tanpa pusing.
  • Membaca struct tag seperti `json:"-"` yang akan sering muncul di model.

Bab ini adalah bab terpenting sebelum masuk ke Fiber. Model User, Post, controller, dan request di aplikasi kita semuanya adalah struct. Pointer juga muncul di hampir setiap baris query database. Pelan-pelan saja, coba setiap contohnya.

Struct: cetakan data

Sejauh ini kita menyimpan data di variabel terpisah: nama, nim, ipk. Repot kalau datanya banyak. Struct mengumpulkan beberapa data yang saling berhubungan menjadi satu tipe baru.

Analogi: struct itu seperti formulir kosong (KTP kosong). Formulirnya menentukan kolom apa saja yang ada: nama, NIK, alamat. Setiap orang yang mengisi formulir itu menghasilkan satu data (KTP milik Budi, KTP milik Siti).

  • type Mahasiswa struct { ... } — membuat tipe baru bernama Mahasiswa. Setiap baris di dalamnya adalah field: nama lalu tipe.
  • Mahasiswa{Nama: "Budi", ...} — struct literal, cara mengisi data. Selalu tulis nama field-nya supaya jelas dan tidak tertukar.
  • budi.Alamat.Kota — titik dipakai untuk masuk ke field, bahkan bertingkat.
  • var kosong Mahasiswa — field yang tidak diisi otomatis berisi zero value: string kosong, 0, false.
  • %+v — format Printf yang mencetak struct lengkap dengan nama field-nya. Sangat berguna saat debugging.
  • []Mahasiswa{...} — slice berisi struct. Di dalam slice, nama tipe boleh dihilangkan: cukup {Nama: "Siti", ...}.
🟥 Kalau di PHP/Laravel...Struct mirip class yang hanya berisi properti. Model Eloquent $user->name di Go menjadi user.Name. Go tidak punya class, extends, atau new. Semua dibangun dari struct, method, dan interface.

Method: function milik struct

Method adalah function yang "ditempel" ke sebuah tipe. Bedanya dengan function biasa hanya ada tambahan receiver di depan nama function: func (c Counter) Info(). Receiver c itu mirip $this di PHP.

Ada dua jenis receiver, dan bedanya penting:

  • func (c Counter) TambahSalah() — value receiver. Method menerima fotokopi data. Mengubah fotokopi tidak mengubah dokumen asli. Hasilnya, nilai tetap 0.
  • func (c *Counter) Tambah() — pointer receiver (perhatikan bintang *). Method menerima alamat data asli, jadi perubahannya tersimpan.
💡 Aturan praktisKalau method perlu mengubah data, atau struct-nya besar, pakai pointer receiver (x *Tipe). Di aplikasi kita, semua method controller memakai pointer receiver: func (p *PostController) Index(c *fiber.Ctx) error. Kalau ragu, pakai pointer receiver.

Pointer: alamat rumah

Bayangkan kamu ingin teman mengecat rumahmu. Ada dua cara:

  1. Kamu membuat miniatur rumahmu dan memberikannya. Teman mengecat miniatur. Rumah aslimu tetap tidak berubah. Inilah yang terjadi saat Go mengirim nilai (salinan).
  2. Kamu memberikan alamat rumah. Teman datang ke alamat itu dan mengecat rumah aslinya. Inilah pointer.

Hanya dua simbol yang perlu kamu hafal:

SimbolDibacaContohArtinya
&"alamat dari"&umurAmbil alamat variabel umur
* di depan tipe"pointer ke"*PostTipe "alamat dari sebuah Post"
* di depan variabel"isi dari alamat"*alamatBuka alamat, ambil atau ubah isinya

Angka 0x... adalah alamat memori. Angka di komputermu pasti berbeda, dan itu normal.

  • *alamat = 21 — mengubah isi lewat alamat. Variabel umur ikut berubah, karena keduanya menunjuk ke tempat yang sama.
  • isiPost(&post, 7) — kita mengirim alamat post, jadi function bisa mengisi variabel milik kita.
  • gantiJudulSalinan(post) — kita mengirim salinan. Judul asli tidak berubah.
  • var kosong *Post — pointer yang belum menunjuk ke mana pun bernilai nil.
ℹ️ Inilah kenapa GORM butuh &Di aplikasi kita akan sering muncul: isiPost(&post, 7) di atas adalah versi mini dari cara kerja First(&post, 1). GORM harus mengisi variabel kita, jadi kita memberikan alamatnya.
⚠️ Awas pointer nilMengakses field dari pointer nil (misalnya kosong.Title) membuat program panic: invalid memory address or nil pointer dereference. Ini salah satu error paling sering dialami pemula. Selalu pastikan pointer sudah terisi, atau cek dulu dengan if p != nil.

Constructor: function NewXxx()

Go tidak punya new Class() atau __construct. Sebagai gantinya, programmer Go membuat function biasa berawalan New yang mengembalikan pointer:

&PostController{} artinya "buat PostController baru, lalu berikan alamatnya". Di routes/web.go nanti kita memanggil post := controllers.NewPostController().

Struct tag: label untuk library lain

Tulisan di antara backtick (`...`) setelah field disebut tag. Go sendiri tidak memakainya. Tag adalah "stiker petunjuk" yang dibaca library lain:

TagDibaca olehContohArtinya
jsonencoding/json, Fiberjson:"user_id"Nama key di JSON

Mari lihat efek tag json secara langsung:

  • json.Marshal mengubah struct menjadi teks JSON. Password tidak ikut karena tag json:"-". Bio juga hilang karena kosong dan bertanda omitempty.
  • json.Unmarshal melakukan kebalikannya. Perhatikan &baru: lagi-lagi kita memberi alamat supaya variabelnya bisa diisi.
🟥 Kalau di Laravel...json:"-" sama dengan protected $hidden = ['password']; di model Eloquent. Model User di aplikasi kita memakai tag ini, jadi password tidak pernah bocor lewat API.

Embedding: "menanam" struct

Go tidak punya pewarisan (extends). Sebagai gantinya ada embedding: menulis nama struct lain tanpa nama field. Field dan method struct itu ikut bisa dipakai langsung.

ℹ️ Contoh nyataGORM menyediakan gorm.Model berisi ID, CreatedAt, UpdatedAt, DeletedAt. Kamu bisa menanamnya di model. Di modul ini kita menulis field-field itu satu per satu supaya lebih jelas.

11Interface, any & Type Assertion

Tujuan bab
  • Memahami interface sebagai "kontrak" perilaku.
  • Mengerti kenapa error sebenarnya adalah interface.
  • Memakai any, type assertion x.(T), dan type switch.
  • Membaca kode seperti c.Locals("authUser").(*models.User) di aplikasi kita.

Interface: kontrak perilaku

Struct menjawab pertanyaan "data ini berisi apa?". Interface menjawab pertanyaan lain: "data ini bisa melakukan apa?".

Analogi: lowongan kerja "Dicari sopir: harus bisa menyetir". Perusahaan tidak peduli pelamarnya bernama Budi atau Siti, lulusan mana, atau tinggal di mana. Syaratnya cuma satu: bisa menyetir. Interface adalah lowongan itu. Siapa pun yang memenuhi syarat otomatis diterima.

  • type Shape interface { Luas() float64; Nama() string } — daftar method yang wajib dimiliki. Interface tidak berisi data, hanya daftar kemampuan.
  • Persegi dan Lingkaran punya kedua method itu. Hasilnya, keduanya otomatis dianggap Shape. Tidak ada kata implements.
  • func cetak(s Shape) menerima bentuk apa saja. Besok kalau kita menambah Segitiga, function cetak tidak perlu diubah sama sekali.
  • []Shape{...} — satu slice bisa berisi tipe berbeda, asalkan semuanya memenuhi kontrak Shape.
🟥 Kalau di PHP/Laravel...PHP: class Persegi implements Shape — harus ditulis jelas. Go: cukup punya method yang sama, otomatis cocok (implicit). Konsepnya sama dengan Contract di Laravel, misalnya Illuminate\Contracts\Mail\Mailer: kode kita bergantung pada kontrak, bukan pada kelas tertentu.

Contoh yang lebih "dunia nyata"

Aplikasi ingin mengirim notifikasi saat user mendaftar. Hari ini lewat email, bulan depan mungkin lewat WhatsApp. Dengan interface, kode pendaftaran tidak perlu tahu caranya:

Function daftarkanUser hanya bicara dengan kontrak Notifier. Mengganti email menjadi WhatsApp cukup dengan mengganti argumen. Ini juga membuat kode mudah dites: saat testing, kita bisa memberi Notifier palsu yang tidak benar-benar mengirim apa-apa.

error juga interface!

Sekarang misteri di Bab 9 terjawab. Di dalam Go, error didefinisikan seperti ini:

Jadi tipe apa pun yang punya method Error() string otomatis adalah error. Itulah kenapa *ValidationError di Bab 9 bisa dikembalikan sebagai error. Begitu juga *fiber.Error yang dipakai Fiber untuk error 404, 403, dan seterusnya.

ℹ️ Bentuk handler di FiberKamu akan sering melihat fiber.Handler. Ini bukan interface, melainkan nama lain untuk tipe function func(*fiber.Ctx) error. Perhatikan nilai kembaliannya: interface error. Itulah kenapa method controller dan middleware kita semuanya punya bentuk yang sama: menerima c *fiber.Ctx dan mengembalikan error.

any: kotak yang bisa diisi apa saja

any adalah interface kosong (nama lainnya interface{}). Interface kosong tidak mensyaratkan method apa pun, jadi semua tipe memenuhinya. any seperti kardus tanpa label: bisa diisi buku, sepatu, atau piring.

Masalahnya: kalau kardusnya tidak berlabel, saat dibuka kita harus menebak isinya. Menebak isi kardus inilah yang disebut type assertion.

Di Fiber, data yang kamu titipkan dengan c.Locals("kunci", nilai) disimpan sebagai any. Begitu juga isi session. Contoh berikut meniru keadaan itu dengan map[string]any:

1. Type assertion biasa: x.(T)

locals["authUser"].(*User) artinya "aku yakin isi kotak ini *User, berikan sebagai *User". Kalau tebakannya salah, program panic. Jadi bentuk ini hanya dipakai jika kamu benar-benar yakin.

2. Bentuk aman: v, ok := x.(T)

Dengan tambahan ok, Go tidak panic. Kalau tebakan benar, ok bernilai true. Kalau salah (atau kotaknya kosong), ok bernilai false dan v berisi zero value.

3. Type switch: switch v := x.(type)

Dipakai kalau isinya bisa beberapa kemungkinan tipe. Di setiap case, variabel nilai sudah otomatis bertipe sesuai case-nya.

ℹ️ Ketemu lagi di aplikasi kita Perhatikan pilihannya. Di controller yang sudah dijaga middleware Auth, kita yakin, jadi pakai bentuk biasa. Di middleware yang berjalan untuk semua pengunjung (termasuk tamu), kita pakai bentuk aman.
⚠️ Tipe harus persis samaKalau yang disimpan uint, tebakan .(int) akan gagal, walau sama-sama angka. Type assertion tidak mengonversi tipe. Ini sumber bug yang sering bikin bingung.

Cukup dengan memiliki semua method yang diminta interface itu. Tidak perlu menulis implements.

14Dasar Web: HTTP, Request & Response

Tujuan bab

  • Mengenal bagian-bagian URL, HTTP method, status code, header, dan body.
  • Memahami kenapa butuh cookie dan session.

Sebelum memakai Fiber, kita perlu paham "bahasa" yang dipakai web. Semua framework web (Laravel, Fiber, Express, Django) hanyalah alat untuk berbicara dengan bahasa yang sama: HTTP. Kalau paham HTTP, kamu akan paham framework apa pun.

Client dan server

Analogi: restoran.

  • Client (browser, aplikasi HP, atau curl) adalah pelanggan. Ia memesan sesuatu.
  • Server (program Go kita) adalah dapur. Ia menerima pesanan, memasak, lalu mengirim hasilnya.
  • Request adalah kertas pesanan. Response adalah piring makanan yang diantar balik, lengkap dengan nota.
Browser— request →Server Go— response →Browser

Satu kali klik di browser = satu request dan satu response. Membuka satu halaman bisa memicu banyak request sekaligus: HTML-nya, CSS, gambar, dan lain-lain.

HTTP itu pelupa: cookie dan session

HTTP bersifat stateless: setiap request berdiri sendiri. Server tidak ingat bahwa request barusan berasal dari orang yang sama dengan request sebelumnya. Jadi bagaimana server tahu kamu sudah login?

Analogi: gelang tiket konser.

  1. Di pintu masuk, kamu menunjukkan tiket (login dengan email + password).
  2. Petugas memberimu gelang bernomor, misalnya "A-123" (server mengirim cookie berisi ID session).
  3. Petugas mencatat di bukunya: "A-123 = Budi, tiket VIP" (server menyimpan session: user_id = 1).
  4. Setiap kali kamu masuk area lain, cukup tunjukkan gelang (browser otomatis mengirim cookie di setiap request). Petugas mencocokkan dengan bukunya.

Web server pertama dengan net/http

Go sudah punya library web bawaan: net/http. Mari buat server kecil tanpa framework, supaya kita tahu apa yang sebenarnya terjadi.

  • Handler adalah function dengan bentuk func(w http.ResponseWriter, r *http.Request). r berisi request (pesanan). w adalah tempat menulis response (piring).
  • http.NewServeMux() membuat router: penghubung antara URL dan handler.
  • "GET /halo/{nama}" — method + path. {nama} adalah bagian URL yang berubah-ubah, dibaca dengan r.PathValue("nama"). (Fitur ini ada sejak Go 1.22.)
  • r.URL.Query().Get("s") membaca query string. r.FormValue("pesan") membaca data form di body.
  • w.Header().Set(...) mengatur header. w.WriteHeader(201) mengatur status code. http.Error(...) mengirim pesan error beserta status code-nya.
  • http.ListenAndServe(":8080", mux) menyalakan server di port 8080 dan terus menunggu request. Hentikan dengan Ctrl + C.

Kalau net/http bisa, kenapa butuh Fiber?

net/http sudah cukup untuk server kecil. Tapi aplikasi blog kita butuh jauh lebih banyak. Semua ini harus kita tulis sendiri kalau tanpa framework:

Framework adalah kumpulan "alat siap pakai" yang sudah dites banyak orang. Sama seperti Laravel di dunia PHP: PHP murni bisa membuat web, tapi Laravel membuat pekerjaanmu jauh lebih cepat dan rapi.

  2. Middleware global berjalan berurutan: recover, logger, method override, session, CSRF, lalu share data (mengambil user yang login).
  3. Router mencari route yang cocok: POST /posts.
  4. Middleware route auth mengecek: sudah login? Kalau belum, redirect ke /login.
  5. Controller PostController.Store membaca form, memvalidasi, lalu menyimpan lewat model ke database.
  6. Controller menyimpan flash message "Post berhasil dibuat!" lalu redirect ke /posts.
  7. Browser membuka /posts. Controller merender view HTML, dan flash message tampil satu kali.

26Autentikasi: Register, Login, Logout

Tujuan bab
  • Membuat fitur daftar akun dengan password ter-hash.
  • Membuat login dan logout berbasis session.

Konsep dulu: apa itu autentikasi?

Autentikasi artinya membuktikan "kamu siapa". Analoginya seperti check-in di hotel:

  1. Kamu menunjukkan KTP di resepsionis. Ini sama dengan login: mengirim email dan password.
  2. Resepsionis mencocokkan KTP dengan data pemesanan. Ini sama dengan mengecek password di database.
  3. Kalau cocok, kamu diberi kartu kamar. Ini sama dengan session: server mencatat user_id, dan browser menyimpan cookie berisi ID session.
  4. Selama menginap, kamu cukup menunjukkan kartu kamar, tidak perlu KTP lagi. Ini sama dengan request berikutnya: browser mengirim cookie secara otomatis, jadi kamu "tetap login".
  5. Saat check-out, kartu dinonaktifkan. Ini sama dengan logout: user_id dihapus dari session.

Menyimpan password dengan aman: hash

Aturan nomor satu: jangan pernah menyimpan password apa adanya. Kalau database bocor, semua password user ikut bocor. Banyak orang memakai password yang sama di banyak website, jadi kebocoran ini sangat berbahaya.

Solusinya adalah hash. Hash adalah proses "mengacak" teks secara satu arah. Mudah mengubah password menjadi hash, tapi hampir mustahil mengubah hash kembali menjadi password. Analoginya seperti jus jeruk: jeruk mudah dijadikan jus, tapi jus tidak bisa dikembalikan menjadi jeruk utuh.

Password asliYang disimpan di database (contoh)
password$2a$10$L8LPCg5M67/GoUCHNDnnr.h6a7khTFi9YeHlBgsjViY/PH3Wh/iem

Kita memakai algoritma bcrypt, sama seperti Hash::make() di Laravel. Dua function yang kita pakai:

  • bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost) — membuat hash saat register. Hasilnya berbeda setiap kali dipanggil, walaupun passwordnya sama, karena bcrypt menambahkan salt (bumbu acak).
  • bcrypt.CompareHashAndPassword(hash, []byte(password)) — mengecek password saat login. Hasilnya nil kalau cocok, dan berisi error kalau tidak cocok.
ℹ️ Kenapa ada []byte(...)?Library bcrypt bekerja dengan byte, bukan string. []byte("rahasia") mengubah string menjadi slice byte. string(hash) mengubahnya kembali menjadi string supaya bisa disimpan di kolom database. Ini konversi tipe yang kamu pelajari di Bab 4.

Alur register

  1. User membuka GET /register dan melihat form.
  2. User mengisi nama, email, password, dan konfirmasi password, lalu menekan "Daftar". Browser mengirim POST /register.
  3. Controller memvalidasi data, lalu mengecek apakah email sudah dipakai.
  4. Kalau ada yang salah, form ditampilkan lagi beserta pesan error dan isian lama.
  5. Kalau benar, password di-hash dengan bcrypt, lalu user disimpan ke tabel users.
  6. User langsung dibuat login, diberi flash message, lalu diarahkan ke /posts.

Alur login

  1. User mengisi email dan password.
  2. Kita cari user berdasarkan email, lalu cocokkan password dengan hash di database (bcrypt).
  3. Jika cocok, simpan user_id ke session.
  4. Di request berikutnya, middleware ShareViewData membaca user_id dan mengambil data user. Itulah kenapa user "tetap login".
Form login→Validasi→Cari user by email→Cek bcrypt→Session user_id→Redirect /posts

Apa itu API?

API (Application Programming Interface) adalah "pintu" supaya program lain bisa memakai aplikasi kita. Sampai bab ini, yang memakai aplikasi kita adalah manusia lewat browser. Manusia butuh tampilan HTML yang cantik. Program lain, seperti aplikasi Android, aplikasi iPhone, atau frontend React/Vue, tidak butuh tampilan. Mereka hanya butuh datanya.

Analogi: halaman web itu seperti makan di restoran. Makanan disajikan di piring dengan hiasan. API itu seperti layanan katering. Makanannya sama, tapi dikirim dalam kotak polos, dan penerimanya yang menata sendiri.

Mengenal JSON

JSON (JavaScript Object Notation) adalah format teks untuk mengirim data. Hampir semua bahasa pemrograman bisa membacanya. Aturannya sedikit:

  • { } adalah object: kumpulan pasangan "kunci": nilai. Di Go, ini menjadi struct atau map.
  • [ ] adalah array: daftar nilai. Di Go, ini menjadi slice.
  • Nilai bisa berupa string (wajib tanda kutip dua), angka, true/false, null, object, atau array.
ℹ️ Dari struct Go ke JSONIngat struct tag di Bab 10? Tag json:"title" menentukan nama kunci di JSON. Tag json:"-" menyembunyikan field. Fiber mengubah struct menjadi JSON lewat c.JSON(data), dan mengubah JSON menjadi struct lewat c.BodyParser(&req).

Apa itu REST?

REST (Representational State Transfer) adalah gaya merancang API. REST bukan library dan bukan aturan wajib. REST adalah kesepakatan yang dipakai hampir semua developer. Kalau API kamu mengikuti REST, developer lain langsung paham cara memakainya tanpa membaca banyak dokumentasi. API yang mengikuti gaya ini disebut RESTful API.

Autentikasi API dengan token

Di web, kita memakai session dan cookie. Untuk API, cara ini kurang cocok. Aplikasi mobile tidak selalu menyimpan cookie, dan API bersifat stateless. Solusinya adalah token.

Analogi: token itu seperti kartu akses gedung kantor. Kamu menunjukkan KTP sekali di resepsionis (login), lalu menerima kartu akses (token). Setelah itu, kamu cukup menempelkan kartu di setiap pintu (setiap request). Kalau kartu hilang, resepsionis bisa menonaktifkannya (logout / hapus token).

  1. Client mengirim email dan password ke POST /api/login.
  2. Server mengecek password. Kalau benar, server membuat token acak, menyimpan hash-nya di tabel personal_access_tokens, lalu mengirim token asli ke client.
  3. Client menyimpan token itu (misalnya di penyimpanan aplikasi mobile).
  4. Di setiap request berikutnya, client mengirim header: Authorization: Bearer <token>.
  5. Middleware ApiAuth mencari token itu di database. Kalau ketemu, request lanjut ke controller. Kalau tidak, server menjawab 401.
  6. Saat logout, token dihapus dari database. Token itu tidak bisa dipakai lagi.
Client→ login →Server buat token→Client simpan token→ Bearer token →ApiAuth→Controller
🟥 Kalau di Laravel...Ini cara kerja Laravel Sanctum (API token). $user->createToken('api') menjadi support.CreateToken(&user, "api"), dan middleware('auth:sanctum') menjadi middleware.ApiAuth().
ℹ️ Bagaimana dengan JWT?JWT adalah jenis token lain yang berisi data user dan tanda tangan digital. Server tidak perlu mengecek database. Kelemahannya, JWT sulit dibatalkan sebelum kedaluwarsa. Untuk pemula, token yang disimpan di database (seperti Sanctum) lebih mudah dipahami dan logout-nya pasti bekerja. JWT ada di tugas pengembangan Bab 35.
⚠️ Token = passwordSiapa pun yang memegang token bisa bertindak sebagai user tersebut. Jangan menampilkan token di log, jangan mengirim token lewat URL (?token=...), dan pakai HTTPS di server produksi.

Kuis singkat

2. Apa gunanya API Resource seperti resources.Post()?

Menentukan bentuk JSON yang keluar, sehingga data sensitif (misalnya email penulis) tidak ikut terkirim. Bentuk JSON juga tetap stabil walaupun model berubah.

3. Kenapa ApiAuth menjawab 401, sedangkan Auth versi web melakukan redirect?

Client API bukan browser, jadi tidak bisa menampilkan halaman login. Status 401 memberi tahu client bahwa ia harus login (mengambil token) dulu.

4. Tag apa yang harus ada di struct request supaya password_confirmation dari JSON terbaca?

json:"password_confirmation".

35Latihan & Evaluasi

Kuis pemahaman

1. Apa padanan @yield('content') Blade di modul ini?

{{embed}} di file layout layouts/main.html.

2. Kenapa /posts/create harus didaftarkan sebelum /posts/:id?

Karena Fiber mencocokkan route dari atas ke bawah. Jika /posts/:id lebih dulu, kata "create" dianggap sebagai nilai :id.

3. Apa fungsi c.Next() di middleware?

Melanjutkan request ke middleware berikutnya atau ke controller. Setara $next($request) di Laravel.

4. Bagaimana cara form HTML mengirim request DELETE?

Kirim dengan method POST dan tambahkan <input type="hidden" name="_method" value="DELETE">. Middleware MethodOverride mengubah method-nya.

5. Bagaimana cara menyembunyikan field dari output JSON?

Beri tag json:"-" pada field struct, seperti field Password di model User.

6. Di dalam {{range .posts}}, bagaimana mengakses token CSRF?

Pakai {{$.csrf}}. Tanda $ menunjuk ke data paling luar.

7. Apa arti if err != nil?

"Kalau ada error". Function Go mengembalikan error sebagai nilai biasa. nil berarti tidak ada error.

8. Kenapa database.DB.First(&post, id) memakai tanda &?

Supaya GORM bisa mengisi variabel post yang asli lewat alamatnya (pointer), bukan salinannya.

9. Apa beda halaman web dan RESTful API di modul ini?

Web mengirim HTML dan memakai session + cookie. API mengirim JSON, memakai token di header Authorization: Bearer, dan memberi hasil lewat status code.

10. Kapan memakai status 401, 403, dan 422?

401: belum login atau token salah. 403: sudah login tapi tidak berhak. 422: data yang dikirim tidak lolos validasi.

Tugas pengembangan

  1. Pagination — Tampilkan 5 post per halaman di /posts?page=2. Petunjuk: c.QueryInt("page", 1), lalu DB.Limit(5).Offset((page-1)*5).
  2. Pencarian — Tambah form cari di halaman daftar post. Petunjuk: Where("title LIKE ?", "%"+q+"%").
  3. Kategori — Buat model Category dan relasi Post belongsTo Category. Jangan lupa tambahkan ke Migrate().
  4. Komentar — User yang login bisa berkomentar di detail post.
  5. Upload gambar — Tambah gambar sampul post. Petunjuk: c.FormFile("image") dan c.SaveFile(file, "./public/uploads/"+nama). Jangan lupa ubah form menjadi enctype="multipart/form-data".
  6. API dengan JWT — Ganti token database di Bab 30 dengan JWT (paket github.com/gofiber/contrib/jwt). Bandingkan kelebihan dan kekurangannya.
  7. API komentar — Buat endpoint GET/POST /api/posts/:id/comments lengkap dengan validasi dan token.
  8. Rate limit — Batasi POST /api/login maksimal 5 kali per menit dengan limiter.New().
  9. Generator lain — Tambahkan perintah make:model dan make:middleware di app/console/make.go.
